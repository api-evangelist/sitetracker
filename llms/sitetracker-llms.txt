## What an agent needs to know first

Sitetracker does not operate an API host, publish an API reference, or ship a machine-readable
contract. Its programmable surface is the **Salesforce Platform API** over the Sitetracker
managed package's standard and custom objects. Sitetracker's own words:
"You can build apps, automations, and integrations using REST, SOAP, Bulk, and other APIs — with
full support for custom and standard objects" and "Sitetracker objects are API-ready and work
seamlessly with standard Salesforce connectors and tools."

Practically, this means:

- The base URL is the **customer's own Salesforce org**, e.g.
  `https://{myDomain}.my.salesforce.com/services/data/{version}/` — there is no
  `api.sitetracker.com`, and that hostname does not resolve.
- Authentication is **Salesforce OAuth 2.0** via a connected app. Sitetracker issues no keys and
  operates no authorization server.
- Object names, field names, and the Sitetracker-specific integration guide are documented behind
  a Salesforce Community login at help.sitetracker.com and community.sitetracker.com. An
  unauthenticated agent cannot read them.
- Rate limits, error semantics and API versioning are all Salesforce's, not Sitetracker's.
